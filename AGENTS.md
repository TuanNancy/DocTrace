# Repository Notes

## Commands and verification

- CI uses Ubuntu 24.04, Python 3.12 / Node 22; Actions run on Node 24. Run Python/npm commands in `backend/`/`frontend/`; Docker/deploy commands run at root.
- Backend setup: `python -m pip install -r requirements-dev.txt` includes runtime + tests; run `alembic upgrade head` against a configured Postgres before workspace features; API: `uvicorn app.main:app --reload --port 8000`. Linux worker: `python -m app.worker`; on macOS use `docker compose --profile jobs up -d --build worker` for Linux RQ fork behavior.
- Backend tests: `python -m pytest`; focused: `python -m pytest tests/test_document_repository.py tests/test_worker.py`, `python -m pytest tests/test_provider_usage.py tests/test_provider_calls.py`, `python -m pytest tests/test_conversations.py tests/test_transcripts_pg.py`, or `python -m pytest tests/test_chat.py::test_chat_sse_stream`. `tests/conftest.py` seeds isolated config before app import. Repository tests use fakeredis; router tests override Auth, `require_workspace`, repository, `get_rate_limiter`, quota and transcript services to avoid developer services. Postgres workspace/quota/transcript integration tests use testcontainers and skip without Docker.
- RAG evaluation: `python -m evals --mode smoke` is deterministic and runs in CI; `--mode live` needs `OPENROUTER_API_KEY` and a positive `--budget-micros` (optional `--request-cap-micros`). `.github/workflows/eval-live.yml` runs nightly/manual with the separate `OPENROUTER_EVAL_API_KEY`; update `backend/evals/baseline.json` only with `--write-baseline` and review the diff. Retrieval debugging: `python scripts/inspect_retrieval.py <user_id> <doc_id> "câu hỏi" [--workspace-id <uuid>]` prints real scores before changing `MIN_RELEVANCE_SCORE`.
- Redis integration: `python scripts/verify_rate_limits.py` checks real Lua/TTL/concurrency; `python scripts/verify_document_queue.py` checks transactions and Linux RQ workers with PDF/AI/S3/Milvus fixtures. Both need running Docker and use disposable Redis. Queue verification builds an image unless given `--api-image doctrace-api:verify`.
- Workspace backfill: `python scripts/backfill_workspaces.py` is a dry run; `--apply` persists `workspace_id`/`owner_user_id`, personal workspaces and every sorted-set index under per-document WATCH/MULTI. Deleted hashes stay as tombstones and are removed from all indexes. Check index additions/removals as well as hash updates. Keep the legacy per-user index; never flush Redis or recreate Milvus.
- Frontend: `npm ci`; CI order: `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:e2e`, `npm run build`. Focused: `npm test -- tests/ChatWindow.test.tsx`. Build needs public Supabase settings; `.github/workflows/verify.yml` supplies placeholders.
- Before E2E: `npx playwright install chromium` (`--with-deps` on Linux CI). Playwright builds then starts Next in production mode with fixture env for both steps; keep ports 4310/4311 free for Next + fake Auth/API. E2E replaces `.next`; rebuild with deployment env before normal `npm start`/deployment. Screenshots go to ignored `test-results/`. Headless shell downloads PDFs; assert the URL/page fragment rather than Chrome's viewer.
- Validate production Compose with fixture env: `BACKEND_ENV_FILE=./deploy/tests/api.env MIGRATION_ENV_FILE=./deploy/tests/migrations.env docker compose --env-file .env.production.example -f compose.production.yml config --quiet`.
- Proxy verification: `docker build -t doctrace-api:verify ./backend`, then `python deploy/tests/verify_nginx.py --api-image doctrace-api:verify`. It uses disposable containers/self-signed TLS. Use the certificate-test Docker command in `.github/workflows/verify.yml`; the production image excludes test dependencies, scripts and fixtures, so deploy tests are mounted.
- Changes land as one PR per phase after the local suites above pass. Production deploy is part of CI: a push to `main` runs `.github/workflows/verify.yml` and, only if backend/frontend/deployment pass, the `deploy` job streams `deploy/deploy.sh deploy <sha>` over SSH (serialized by `doctrace-production`; recreating the worker can take up to its 16m graceful stop). Roll back with `bash deploy/deploy.sh rollback` (or the `recover.sh rollback` printed on failure); release state lives in `.git/doctrace-deploy/{current,pending,previous}`. Never hand-edit the VPS checkout or treat an env edit as a deploy; even a docs-only merge rebuilds and redeploys.

## Runtime boundaries

- Paths in this section are relative to `backend/app/`. See `ARCHITECTURE.md` for lifecycle and recovery details.
- FastAPI starts in `main.py`. Upload retains the PDF in Supabase Storage, then commits Redis metadata + RQ enqueue before returning 202. Indexing errors belong to document status. Supabase supplies Auth/Storage and the Postgres control plane (`doctrace` schema via Alembic); no metadata service-role key is required. Redis remains authoritative for the document catalog/queue.
- `core/workspace.py` requires `X-Workspace-Id` for upload, documents/files/chunks, chat and usage. Authentication runs first; missing header is `400 workspace_required`, malformed UUID is `400 workspace_invalid`, and inactive/non-member is `404 workspace_not_found`. Workspace management routes use path IDs, not the header.
- `services/workspaces.py` owns membership, roles, plan workspace limits, archive/restore and personal provisioning (demo personal workspace id equals the owner user id). HTTP upload commits through `create_document()` after Storage: it locks active workspace then membership through the Redis transaction. Removal locks in the same order, sets `removing`, counts Redis under the lock and commits `removed`; errors roll back to active. Never pass a previously read count to removal or bypass admission with raw repository create in HTTP routes. Owners and platform admins see metadata/aggregates, never member PDFs or transcripts.
- Member adds authorize the owner before `doctrace.auth_user_exists(uuid)` checks active Auth-user existence, including duplicate/reactivation paths. Migration `0002` supplies the private boolean `SECURITY DEFINER` helper; runtime has EXECUTE only, no Auth schema/table grants. Hosted `postgres` cannot delegate Auth schema USAGE. Keep the fixed empty search path, `row_security=off`, migration-owner Auth read/bypass rights and PUBLIC/Data API EXECUTE revocations; readiness checks and probes this boundary. Postgres fixtures model a non-superuser migration identity without Auth schema grant option.
- `services/document_repository.py` owns Redis hashes and sorted sets under `doctrace:library:v2`: `document:{doc_id}`, `workspace:{wid}:user:{uid}:documents`, `workspace:{wid}:documents`, `documents`, plus the legacy `user:{uid}:documents` during rollout. Catalog keys have no TTL. RQ result expiry must not remove ready documents. Every read/mutation checks workspace + owner; Milvus queries also filter `user_id`. Pre-P1 records without workspace metadata normalize to the owner's personal workspace on read. `create(..., limit=...)` watches the workspace document set and re-counts under WATCH/MULTI; upload deletes the retained PDF when that atomic re-check returns 429.
- `services/rate_limiter.py` uses atomic Redis-time windows under `doctrace:ratelimit:v1` with TTL. Validate user/document before quota; check quota before Storage/enqueue/SSE. Never refund admissions or retry uncertain quota replies. Redis failure is 503; burst exhaustion is 429 + `Retry-After` with `code: "rate_limited"`, which CORS and fetch/XHR must preserve. Deletion retries are exempt.
- `services/quotas.py` owns monthly plan quota and idempotency, separate from the Redis burst limiter. `plan_limits` seeds free `10/5/1`, pro `100/50/10` for questions/documents/workspaces. `admit_chat()` inserts `chat_requests`, creates/finds the conversation, inserts the user message + `pending` assistant placeholder and increments the UTC-month `usage_counters` row in one Postgres transaction (`used < limit`), so concurrency cannot overshoot; a failure rolls everything back. Client `request_id` is optional; use `uuid4()` when absent and keep it stable for duplicate retries. Duplicate codes are `409 request_completed` / `request_in_progress` / `request_failed` with no extra charge. Chat marks `streaming` then a terminal `completed`/`failed`/`interrupted` in a shielded scope. `/api/usage` merges Postgres counters/costs with the Redis workspace document count; owners see every user, members only self. Quota exhaustion is 429 `quota_exceeded` with `reset_at`; document quota has no monthly reset.
- `services/transcripts.py` owns owner-scoped transcript reads, deletion, streaming finalization, stale generation marking and retention. Every query filters workspace + user; owners/platform admins cannot read member transcripts. Routes are `GET /api/conversations`, `GET/DELETE /api/conversations/{id}`. “Chat mới” physically deletes the current conversation and blocks client submission until deletion resolves. HTTP document delete/retry uses `queue_document_deletion()`: a transaction advisory lock shared with chat admission fences Redis acceptance and SQL retention. Rejected deletes preserve transcripts; reads batch-check Redis visibility; the worker retries retention before external cleanup after uncertain SQL commits. Preserve `delete_requested_at` through retries. `TRANSCRIPT_DELETE_MODE` is `retain_30d` (default) or `cascade`; `TRANSCRIPT_RETENTION_DAYS` defaults to 30. `python -m app.purge_transcripts` deletes expired conversations and keeps `provider_calls`; repository systemd units schedule 03:00 UTC. Stale sources compare each message `index_id` with the current ready document's `active_index_id`.
- `routers/admin.py` (`/api/admin`) requires a `doctrace.platform_admins` row (403 otherwise) and exposes overview, workspaces, plan changes, purge, retry, health and audit. Admin retry also accepts only `error`/`delete_error`, writes the audit intent before touching Redis, and rechecks lifecycle under the lock.
- `services/job_queue.py` enqueues inside the repository's WATCH/MULTI transaction. RQ 2.12 `unique=True` ignores a supplied pipeline: do not enable it here. API/worker need the same Redis and queue (`documents-v2`); legacy `documents` jobs have incompatible payloads.
- `worker.py` uses JSON serialization and the retry scheduler; `jobs/documents.py` creates clients after fork. Keep worker blocking Redis timeouts separate from producer timeouts. `job_queue.MAX_RETRIES` also controls attempt numbering. Redis/RQ/boto3/Milvus blocking calls run off-loop.
- Public `doc_id` differs from the Milvus generation: resolve `active_index_id`. A retry registers a fresh generation; only current job/attempt may publish. Reread metadata after an uncertain enqueue/publication before cleanup or failure. Delete/retry rejects live RQ jobs, including scheduled retries; RQ `finished` alone never implies ready.
- `services/pdf_indexing.py` owns indexing and temporary-file cleanup. `processors/pdf.py:load_pdf_pages()` preserves the original filename and **one-based physical PDF pages**, including blanks, for `#page=N`.
- `providers/usage.py` and `services/provider_calls.py` own metered accounting. `provider_calls` comes from migration `0001`; P2a adds no schema migration. Store cost as integer micro-USD (`cost_micros`), never float; missing cost is `NULL` + `cost_status='unknown'`, never `0`. Embedding batches aggregate into one call row and the dimension probe is excluded. Missing costs reconcile once through `GET /generation`; repeated `generation_id` upserts, never duplicates. Tracking is best effort and disabled without `DATABASE_URL`; DB/reconciliation failures must not fail chat or indexing. Costs never appear in SSE. `SUMMARY_MAX_CALLS` (default 8) is a hard pre-answer cap. SDK retries are disabled so one logical call maps to one HTTP attempt.
- Chat retrieves once, bounds ordinary context before citation numbering, and streams using those same chunks. Summaries read all owner-scoped chunks without query embeddings; preserve citation IDs through reduction (`score: null`).
- Admission runs before the answer cache: a cache hit still consumes one question and sets `chat_requests.cache_hit`; cache read/write failures are misses and never fail chat. The cache key binds workspace/owner/doc/`active_index_id`/query/language/model/prompt version/retrieval and context settings/temperature/overview, so re-index or policy changes cannot reuse stale answers. `choose_route` is opt-in (`MODEL_ROUTING_ENABLED` + `CHEAP_MODEL`): free plan uses the cheap model, pro keeps `RAG_MODEL`; provider errors never silently reroute. Reasoning models must get `reasoning.enabled=false` (`MODEL_REASONING=off`) or hidden thinking consumes `RAG_MAX_TOKENS` and can empty the stream; summaries always disable reasoning.
- SSE sources require `citation_id`, `chunk_id`, public `doc_id`, `page`, `source`, `score`; token is a JSON text delta, error is `{message}`, done is the JSON string `"[DONE]"`. The chat response exposes additive `X-Conversation-Id` (not an SSE event). Persisted sources gain `stale` on transcript reads when the generation changed. Keep `routers/chat.py`, frontend types/parser and fixtures aligned; EOF without done is an error. Citation lookup checks workspace + owner + active generation; request fresh 300-second PDF links when opening.

## Frontend ownership

- `frontend/src/app/(workspace)/layout.tsx` mounts `WorkspaceProvider` for `/chat`, `/documents` and `/usage`. It owns auth/workspace list/catalog and the chat/upload hooks; `ChatWindow` and `UploadZone` receive required sessions, not their own hook instances. Navigation preserves state; switching PDFs/workspaces clears chat. Reload restores the latest ready conversation for the workspace; “Chat mới” deletes the current transcript. Backend chat is single-turn.
- `WorkspaceProvider` fetches `/api/workspaces` after auth, defaults to the active personal workspace and aborts/clears document, source, chat, upload and late responses on switch. Archived/purging memberships stay listed but are not selectable. Document/chat transport must send `X-Workspace-Id`; missing selection is a client error. `/usage` renders plan counters, reset date and owner-scoped cost aggregates from `GET /api/usage`.
- `frontend/src/lib/api.ts` owns HTTP transport; `sse.ts` validates/decodes events. `ApiError` preserves status and the structured `{code, message}` detail. Preserve hook cancellation and late-response rejection. Markdown citation transforms must leave code/existing links intact and bind only known IDs. Stale citations must render as plain text and their source cards must stay disabled.
- `/api/usage` uses `scope=workspace` for owners and `scope=self` for members; member counts/costs are self-only and `remaining=null` prevents leaking shared totals. `costs.known_micros`/`unknown_calls` describe recorded costs in the UTC month; display USD, retain integer micro-USD in storage. Clear usage on identity/workspace/role changes and abort both initial and manual refreshes.
- Chat retries keep the logical `request_id` after uncertain replies and EOF without done; never auto-retry POST. `ApiError.detail` and `retryAfter` preserve recovery/quota metadata. Completed duplicates restore the scoped transcript; in-progress duplicates keep the id; failed duplicates require an explicit new charged request. Auth token renewal preserves recovery via `userId`; selection/identity changes clear it.
- Supabase helpers live in `frontend/src/lib/supabase/`. Browser singleton is SDK-managed; server clients are per request. Middleware verifies `getUser()` for both workspace routes and preserves refreshed cookies on redirects plus `private, no-store` headers.
- Google login uses GIS `GoogleLogin` → `signInWithIdToken` on that shared SSR browser client; a plain supabase-js client loses middleware-visible cookies. `NEXT_PUBLIC_GOOGLE_CLIENT_ID` must match the Supabase provider; authorize frontend origins in Google. `/auth/callback` handles legacy Supabase PKCE, not Google credentials. GIS receives a hashed nonce, Supabase the raw nonce; Playwright intercepts GIS locally (see `frontend/README.md`).
- `NEXT_PUBLIC_*` changes require rebuild. API URL is an origin without `/api`; empty enables demo upload/chat while Auth still uses Supabase.
- Workspace styling stays light independently of the landing-page theme; Inter via `--font-sans` applies throughout. `@fontsource-variable/inter` bundles font files locally; builds must not fetch Google Fonts.
- Route moves can leave stale `.next/types`; regenerate ignored Next output rather than changing TypeScript paths. Preserve root `.gitignore` exceptions for `frontend/src/lib/` (Python's `lib/` rule otherwise hides it).

## Configuration and operations

- `AppConfig(...)` never reads env; `from_env(mapping)` parses settings. `get_config()` precedence is `backend/.env` > process env > root `.env`, cached once. Restart API/worker after edits; exporting a variable cannot override `backend/.env`.
- Pass the same config through pipeline/factories/embedder. `RAG_MODEL`/`EMBEDDING_MODEL` are explicit; cached embedder construction makes a real dimension-probe request. Milvus URI mode defaults to AUTOINDEX; preserve request-owned aliases, Strong consistency and cancellation cleanup. `ensure_collection()` rejects incompatibility; only `recreate_collection()` deletes all chunks.
- Changing embedding dimension needs a new `MILVUS_COLLECTION`; keep the old one for rollback. Existing documents stay `ready` but their chunks are unreachable, so they must be re-uploaded (retry only accepts failed documents). OpenRouter model IDs can disappear: probe `RAG_MODEL`/`EMBEDDING_MODEL` after changing them, because a missing model fails at request time, after SSE `sources`.
- Cost guard uses static prices: `MODEL_INPUT_MICROS_PER_MTOK`/`MODEL_OUTPUT_MICROS_PER_MTOK` (and `CHEAP_*` when routing) must match the configured models; `REQUEST_COST_CAP_MICROS` is a pre-call worst-case estimate, while `provider_calls` stores the provider-reported cost.
- Redis AOF/volume holds the library and queue; `down -v` loses them and production certificates. PDF/vector data cannot rebuild the catalog: do not flush Redis or recreate Milvus to populate metadata. Old PostgreSQL users re-upload; see `DEPLOYMENT.md` cutover. `scripts/backfill_workspaces.py` is the only supported P1 catalog rewrite; keep the legacy per-user index until rollback compatibility is no longer needed.
- Use `compose.production.yml` for VPS API/Redis/worker/Nginx; Vercel builds `frontend/`. Plain root Compose starts local vector infrastructure. API/worker share `REDIS_URL=redis://redis:6379/0` inside Docker.
- Keep worker shutdown grace (16m) above job timeouts (index 900s, delete 300s). Follow `DEPLOYMENT.md` for updates/certificates; bootstrap only initially. Recreate Nginx after template edits; preserve unbuffered uploads/SSE, validation-before-reload and Compose project/volumes. systemd assumes `/opt/DocTrace`.
- `/health` is process liveness; production healthcheck/CD use `/ready`, requiring Redis and Postgres with migration stamp, compatible columns, grants and an unprivileged runtime identity. Probes use separate short-timeout connections; additive schema changes remain rollback-compatible. Update `app/db_contract.py` when runtime schema/access needs change. `get_connection_status()` is local connection state; none verifies cloud/worker health.
- Runtime uses `doctrace_app` via `DATABASE_URL`; migration-only `DIRECT_DATABASE_URL` lives in ignored `backend/.env.migrations` (Compose `MIGRATION_ENV_FILE`), never the API/worker env. Alembic never falls back to runtime credentials and reapplies explicit grants on no-op upgrades. Bootstrap role SQL is in `deploy/postgres/`; password is set separately.
- JSON/text logs emit only registered `LOG_EVENTS`, allow-listed fields and exception class/code frames; never raw messages/arguments/exception values. Document request IDs commit atomically with enqueue and bind worker/thread context; new manual retry/delete admissions replace the ID. `DocumentWorker` sanitizes persisted RQ exception strings. Nginx uses static route labels and privacy-safe access logs; request-level raw error logs are disabled.
